## 3. 선행 오류(precursor error) 타이밍 — ★ 라벨/피처 설계에 직접 영향

고장 시각 기준으로, 그 이전 N시간 안에 같은 설비의 오류가 있었는지를 윈도우를 바꿔가며 측정:

| 윈도우 | 선행 오류 존재 비율 |
|---|---|
| 12h | 4.7% |
| 24h | 8.5% |
| **36h** | **98.0%** |
| 48h | 98.0% |
| 72h~168h | 98.0% (변화 없음) |

**24h와 36h 사이에 절벽이 있습니다.** 즉 선행 오류는 거의 전부 "고장 36시간 전 ~ 24시간 전" 구간에 몰려 있고, **고장 직전 24시간 안에는 오류가 새로 안 뜨는 경우가 대부분(91.5%)**입니다. 이는 `SIMULATOR_PLAN.md`의 `LEAD_HOURS = (44, 52)`(열화 개시~고장 전체 구간) · `RAMP_UP_HOURS = 6`(개시~전조 오류 발동까지) 캘리브레이션과 방향이 일치합니다 — 전조 오류가 고장 훨씬 전에 한 번 튀고, 그 뒤로는 텔레메트리 드리프트만 조용히 진행되다가 고장이 납니다.

반대 방향(오류 하나가 실제로 고장으로 이어지는 비율)도 확인:

| 윈도우 | 오류 → 고장으로 이어짐 |
|---|---|
| 24h | 27.2% |
| 48h | 28.7% |
| 168h | 35.5% |

## 4. 결론 — 계획서 5-2 피처 표에 대한 수정 제안

계획서 5-2는 "최근 24h 오류 유형별 횟수"를 피처로 명시합니다. 그런데 위 3번 결과대로면, **예측 시점이 고장 직전 24시간 구간 어디든, "직전 24h 오류 횟수" 피처는 91.5% 확률로 0입니다** — 실제로 가장 강한 신호(36시간 전 오류)가 이 피처의 시야 밖에 있기 때문입니다. 24h 피처 창만 쓰면 모델이 이 신호를 거의 못 봅니다.

**제안**: 오류-횟수 피처를 24h 하나가 아니라 **24h + 48h 두 창으로 이중화**합니다 (텔레메트리 이동평균의 "3h·24h" 이중창 설계와 같은 패턴). 48h 창이 위 절벽(24h→36h)을 확실히 커버합니다. 라벨 자체("향후 24시간 내 compN 고장")는 그대로 두고, 피처만 더 넓게 봅니다 — 3-2(피처 파이프라인) 작업에서 이렇게 반영할지 확인 부탁드립니다.

## 5. 라벨 정의 (확정)

- **대상**: 설비 × 시각(3시간 간격 샘플링, 계획서 5-2 기준) 별 "향후 24시간 이내 compN 고장" 이진 라벨, 부품별 4개.
- **양성 구간**: 고장 시각 기준 `[고장-24h, 고장)` — 위 2번에서 확인했듯 고장 타임스탬프가 텔레메트리와 정확히 정렬되어 있어 경계 계산에 모호함 없음.
- **전체 양성 슬롯 비율**: 대략 2.08%(겹침 미고려 근사치) — 클래스 불균형이 뚜렷해서, 계획서가 이미 명시한 "정상 클래스 다운샘플링 또는 클래스 가중치"가 필수임을 재확인.
