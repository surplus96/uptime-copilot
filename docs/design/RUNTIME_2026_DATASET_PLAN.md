# 2026년 운영 테스트 데이터 전환

## 원인

실행 DB의 telemetry/errors/failures는 2015~2016년, 정비 이력은 2014년부터 존재한다.
sim_*는 비어 있어 dataset_now가 2016-01-01을 현재로 사용하고, 2015-12-31 고장을
최근 고장으로 판정한다. 완료 이벤트 제외는 자동 스캔에만 적용되어 개별 설비 질문에서는
이미 완료한 오류·고장도 다시 조치 근거로 들어갈 수 있다.

## 전환 방식

1. SQLite 일관된 백업을 만든 후 원본 최신 telemetry를 현재 한국시간 정시로 옮긴다.
   네 테이블에 동일한 초 단위 오프셋을 적용해 오류·고장·정비의 순서와 간격을 유지한다.
2. 운영 테이블에는 2026년 구간만 남긴다. 1년 이상의 전체 이력을 현재까지 모두
   넣을 수는 없으므로 범위 밖 자료는 원본 CSV와 전환 전 백업에서 보존한다.
   모델 학습용 CSV와 학습·검증 날짜는 그대로 두고, 전체 원본의 센서 기준선도 보존한다.
3. 옮긴 기록은 초기 참고 이력이다. 날짜를 옮겼다는 이유로 새 미처리 사고가 되지 않도록
   신규 사고의 시작 시각을 전환 anchor로 기록한다. 기존 감지·완료 목록은 별도 보관한다.
   이를 실제 정비 완료로 기록하지 않는다.
4. 새로운 오류·고장은 전환 이후 자료만 사용하고, 개별 설비 질문에서도 완료 당시의
   evidence_at 이하 근거를 제외한다. 더 새로운 사고는 다시 감지할 수 있어야 한다.
   모델의 오류 횟수에서도 초기 참고·완료된 오류를 제외한다. 시뮬레이터가 부품의
   정비 나이를 초기화한 이후에는 그 기록을 사용해 날짜 이동한 원본 정비가
   시뮬레이션 주입의 경과시간을 덮어쓰지 않게 한다.
5. 시간 범위와 오프셋을 DB 메타데이터에 기록해 재시작·재적재 시 재이동하지 않는다.
   시뮬레이터·완료 시각·표시 시간은 한국시간 기준으로 통일하고 연도 범위를 넘어가면
   기록을 생성하지 않는다.

## 검증

날짜 이동 및 멱등성, 백업, 2026년 범위, 센서 값·기준선 보존, 오류와 정비의 상대 간격,
과거/미래 오류 제외, 완료 근거 제외와 새로운 근거 허용을 회귀 테스트한다.
실행 중 컨테이너를 멈춘 상태에서 운영 DB를 전환하고 재배포 후 실제 조회로 확인한다.
기존 승인 대화·감사 로그·CMMS 작업지시서는 과거 실행 결과이며 날짜를 다시 쓰지 않는다.

## 운영 적용 결과 (2026-10-08)

한국시간 `2026-10-08 09:00:00`을 전환 기준으로 로컬 DB와 Docker 운영 DB에 적용했다.
Docker 운영 DB는 다음 범위다.

| 테이블 | 행 수 | 시작 | 마지막 |
|---|---:|---|---|
| telemetry | 673,000 | 2026-01-01 00:00 | 2026-10-08 09:00 |
| errors | 2,982 | 2026-01-01 02:00 | 2026-10-08 08:00 |
| maint | 2,277 | 2026-01-01 09:00 | 2026-10-08 09:00 |
| failures | 564 | 2026-01-01 09:00 | 2026-10-07 09:00 |

초기 참고 이력은 신규 미처리 사고가 아니다. 기존 미처리 4건은
`archived_runtime_events`에 보관했으며 현재 `/events`는 0건이다.
설비 100대 × 신호 4개의 원본 기준선 400개를 보존했다.
backend/frontend를 재빌드·배포했고 `/simulator/status`에 연도·한국시간·데이터 기준 시각을 표시한다.

운영 DB 복사본과 실제 예측 모델로 신규 고장 긴급 감지 → 완료 후 일반 → 후속 고장 긴급
재감지를 검증했다. 답변 근거에 2015~2016년 날짜 또는 완료된 오류가 남지 않는 것도 확인했다.

Docker 전환 전 DB 백업은 `/app/store/backups/pdm-before-runtime-20261008-093538-607273.db`다.
로컬 백업은 `backend/store/backups/`에 있다. 원본 CSV와 모델 학습 결과는 보존된다.
재시작은 저장된 mapping을 재사용한다. 새 연도의 테스트로 전환하려면 별도 전환이 필요하다.

검사 결과: backend 기본 테스트 경로 312개 통과, 새 DB 초기화·재적재 및 완료 테이블
생성 전 조회 검증을 포함한 날짜 전환 테스트 9개 통과, ruff/mypy 및 frontend ruff 통과.
운영 backend는 재배포 후 healthy이며 전환 기준 시각이 재시작 후 유지됨을 확인했다.
